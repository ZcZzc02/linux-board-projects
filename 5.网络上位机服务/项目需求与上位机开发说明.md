## 一、系统总体架构

```
[传感器/设备]
      │
      ▼
[STM32F767 节点板]  ← AD7606(ADC) + CAN总线 + RS485
      │  LoRa (UART)
      ▼
[STM32G070 网关板]
      │  MQTT over TCP (4G/以太网)
      ▼
[EMQX Broker]  ← 本地部署（国网内网或开发阶段用局域网）
      │  MQTT 订阅
      ▼
[Python 后台服务]  ← 本项目要开发的程序
      │
      ├── 解密（将来：国密 SM4）
      ├── 数据解析（帧格式见下）
      ├── 数据库存储（SQLite / MySQL）
      ├── Web 前端（Flask / FastAPI + 前端页面）
      └── 指令下发（MQTT Publish）
```

## 二、硬件节点说明

### 2.1 节点板：STM32F767IGTx（Apollo V2）

| 外设 | 说明 |
|------|------|
| AD7606 | 8通道同步采样 ADC，SPI2，±5V量程，内部基准 |
| CAN1 | PB8/PB9，500 Kbps，接收中断驱动 |
| RS485 | USART2，PA2/PA3，9600 bps，Modbus RTU 主站模式，读取从站4个保持寄存器 |
| LoRa | UART（连接到网关），帧格式见第三节 |

**AD7606 量程与换算：**
- 量程：±5V（RANGE=LOW）
- 原始值：int16，范围 -32768 ~ +32767
- 电压换算：`V(mV) = raw × 5000.0 / 32767.0`
- 上报单位：0.1V/LSB（即 `reg = mV / 100`）

**当前采集内容：**
- CH0：电压传感器输出（AC RMS + DC）
- CH1：电流传感器输出（AC RMS）
- CH2~CH7：备用通道，全部上报

### 2.2 网关板：STM32G070RBTx

| 外设 | 说明 |
|------|------|
| LoRa | UART3（PB10/11），接收节点数据，透传模式，信道CH23，空中速率19.2K，加密密钥0x2233 |
| 网络 | 4G Cat1（Air780/Air724/EC800M）或 WiFi ESP8266，AT指令透传 TCP |
| MQTT | 手写裸协议（无第三方库），QoS 0，发布采集数据；订阅指令下发 topic |

**⚠️ 网关 MQTT 实现关键事实（切换 HiveMQ 必读）：**

1. **MQTT 库**：完全手写裸协议（`mqtt.c`），从零字节拼包，无 paho/mosquitto 等第三方库
2. **Broker 地址写死**：`main.h` 中 `MQTT_SERVER = "mqtts.heclouds.com"`（OneNET），切换 HiveMQ 需改此处
3. **认证方式**：OneNET HMAC-SHA1 Token 签名（`mqtt.c` MQTT_Init），切换 HiveMQ 需替换为普通用户名/密码
4. **Topic 模板写死**：`wifi_cat1.c` 中硬编码 `$sys/{productID}/{deviceName}/thing/pack/post`，切换后需改为自定义 topic
5. **当前订阅的 5 个 Topic**（OneNET 专用格式）：
   - `$sys/.../thing/property/set` ← 属性下发
   - `$sys/.../thing/sub/login/reply` ← 子设备上线回复
   - `$sys/.../thing/sub/logout/reply` ← 子设备下线回复
   - `$sys/.../thing/pack/post/reply` ← 数据上报回复
   - `$sys/.../thing/sub/property/set` ← 子设备属性下发（指令下发入口）

## 三、LoRa 数据帧格式（网关→上位机的原始数据来源）

### 3.1 帧结构

```
[NODE_ADDR][TYPE][LEN][PAYLOAD ...][CRC_H][CRC_L]
    1字节    1字节  1字节  LEN字节     2字节
```

- **CRC**：使用 STM32G0 **硬件 CRC 单元**（`HAL_CRC_Calculate`），配置为 CRC16/Modbus（多项式 0x8005，输入输出均位反转）
- CRC 覆盖范围：`NODE_ADDR` 到 `PAYLOAD` 末尾（不含 CRC 自身，共 `3+LEN` 字节）

### 3.2 TYPE 定义

| TYPE 值 | 含义 | LEN | PAYLOAD 格式 |
|---------|------|-----|-------------|
| `0x01` | AD7606 数据 | 16 | 8通道 × 2字节，大端，有符号 int16 |
| `0x02` | RS485 数据 | 待定 | Modbus 寄存器数据 |
| `0x03` | CAN 数据 | 待定 | CAN 帧原始数据 |

### 3.3 AD7606 帧示例（TYPE=0x01）

```
[01][01][10][CH0_H][CH0_L][CH1_H][CH1_L]...[CH7_H][CH7_L][CRC_H][CRC_L]
总长：21字节
```

**⚠️ 重要：网关当前只解析 CH0/CH1，CH2~CH7 被丢弃**（`LoRa_TransData` 中只取 `raw_s[0]` 和 `raw_s[1]`）。
节点固件已上报全部8通道，但网关侧需修改才能转发 CH2~CH7。

Python 解析示例：
```python
import struct, crcmod

def parse_ad7606_frame(data: bytes) -> dict:
    # data 为完整21字节
    node_addr = data[0]
    frame_type = data[1]
    length = data[2]          # 应为 16
    payload = data[3:3+length]
    crc_recv = (data[-2] << 8) | data[-1]

    crc_calc = crc16_modbus(data[:-2])
    if crc_recv != crc_calc:
        return None  # CRC 错误

    channels = []
    for i in range(8):
        raw = struct.unpack_from('>h', payload, i*2)[0]  # big-endian int16
        volt_mv = raw * 5000.0 / 32767.0
        channels.append(volt_mv)

    return {'node': node_addr, 'channels': channels}
```

## 三补充、网关当前实际发送的 MQTT Payload 格式

> 这是**现有固件实际发出的内容**，切换 HiveMQ 后 Payload 格式可自行重新设计。

### 网关→Broker（AD7606 数据上报）

**Topic**：`$sys/vySl7CVObW/GW001/thing/pack/post`

**Payload**（JSON 字符串，非二进制）：
```json
{
  "id": "1",
  "version": "1.0",
  "params": [{
    "identity": {"productID": "ZCMq7efM7e", "deviceName": "D001"},
    "properties": {
      "ext_adc_voltage": {"value": 1.523},
      "ext_adc_current":  {"value": 0.234}
    }
  }]
}
```
- `value` 单位：**V**（伏特），由 `ch_mv / 1000.0` 换算
- RS485、CAN 在 `LoRa_TransData` 中目前仅打印日志，**尚未上报到 MQTT**（TODO 状态）

### Broker→网关（指令下发）

**Topic**：`$sys/vySl7CVObW/GW001/thing/sub/property/set`

**Payload 示例**（控制节点1开关）：
```json
{"params": {"deviceName": "D001", "PowerSwitch_1": true}}
```
网关收到后通过 LoRa 向对应节点发送 Modbus RTU 写单寄存器命令（功能码 0x06）。

## 四、MQTT 通信规范（目标：HiveMQ）

### 4.1 Broker 配置（开发阶段）

| 参数 | 值 |
|------|----|
| Broker | localhost 或局域网 IP |
| Port | 1883（开发）/ 8883（TLS，生产） |
| 协议 | MQTT v3.1.1 或 v5.0 |

### 4.2 Topic 规划（建议）

| Topic | 方向 | 说明 |
|-------|------|------|
| `data/node/{node_id}/ad7606` | 网关→后台 | AD7606 采集数据 |
| `data/node/{node_id}/rs485` | 网关→后台 | RS485 寄存器数据 |
| `data/node/{node_id}/can` | 网关→后台 | CAN 原始帧 |
| `data/node/{node_id}/raw` | 网关→后台 | 未解析原始帧（调试用） |
| `cmd/node/{node_id}` | 后台→网关 | 指令下发 |
| `status/node/{node_id}` | 网关→后台 | 节点心跳/状态 |

### 4.3 Payload 格式（建议）

**上行数据（JSON 包装原始帧）：**
```json
{
  "ts": 1746528000123,
  "raw": "01011001020304...",
  "parsed": {
    "ch0_mv": 1523.4,
    "ch1_mv": 234.1
  }
}
```

**指令下发：**
```json
{
  "cmd": "reset",
  "target": "node_addr",
  "params": {}
}
```

## 五、上位机功能需求

### 5.1 核心功能（优先实现）

1. **MQTT 接收**：订阅所有节点 topic，实时接收数据

- 用户权限管理
- 历史数据查询与导出

## 九、关键注意事项

1. **字节序**：AD7606 帧 PAYLOAD 为**大端（big-endian）**，Python 解析用 `struct.unpack('>h', ...)`
2. **CRC 实现**：网关使用 STM32G0 **硬件 CRC 单元**，覆盖从第0字节到倒数第3字节（不含末尾2字节 CRC 本身）
3. **NODE_ADDR**：节点地址存储在 EEPROM，默认为 0x01，按键可重置
4. **采样数据单位**：LoRa 帧内为原始 int16（±32767），网关 JSON 中换算为 **V（伏特）**（即 `raw × 5000.0 / 32767.0 / 1000.0`）
5. **RS485 状态**：无从站时 10ms 超时放弃，`RS485_Poll()` 返回 0 表示无数据，非零表示有效
6. **CAN**：中断驱动，收到帧后设 `can_meas_updated` 标志，帧内容在 `can_meas_id` / `can_meas_dlc` 中
7. **CH2~CH7 数据丢失**：当前网关固件 `LoRa_TransData` 只解析并上报 CH0/CH1，如需全8通道需修改网关固件
8. **RS485/CAN 上报未实现**：`LoRa_TransData` 中 `case LORA_TYPE_CAN` 和 `case LORA_TYPE_RS485` 均为 TODO，只打印日志
