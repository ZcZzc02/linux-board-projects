# K7 项目接手说明

这份文件可以直接发给接手人，也可以直接放到他电脑上的项目根目录后让 Codex 阅读。

## 一句话目标

维护 KICKPI K7 / RK3576 Linux 网关，使 STM32F767 节点板的 LoRa 上行数据（AD7606、CAN、RS485）经 K7 发送到 HiveMQ，并支持 Windows 上位机显示和后台下发到节点板。

## 交接时你只需要收到两样东西

1. 本文件：`同门接手说明.md`。
2. `K7交接包-源码与关键备份-可直接解压.zip`。

正常接手同一块 K7 板子时，不需要先索取或刷写官方系统镜像。ZIP 已包含继续开发所需的源码、关键 UART3 备份、烧录工具和资料。官方全量镜像仅在板子无法启动、确认需要恢复系统时，再向原交接人单独索取。

## 收到后按此操作

1. 在任意目录克隆下面的 GitHub 分支。
2. 将 ZIP **直接解压到 clone 后的项目根目录**，选择“合并/覆盖目录”。ZIP 内的 `1.网关`、`2.节点F767`、`backups` 会落到正确位置。
3. 用 VS Code 打开项目根目录，让 Codex 先阅读 `AGENTS.md`、本文件、`docs/K7项目交接指南.md` 和 `docs/INTERFACE_SPEC.md`。
4. 不要先刷机。先连接 K7 的 ADB，按“`K7 接手验证顺序`”验证现有系统、UART3、LoRa、WiFi 和 HiveMQ。
5. 只有 GitHub 不可访问时，才使用 ZIP 内的 `linux-board-projects-handover.bundle` 离线克隆。

克隆完成后，下面三个关键文件必须存在；ZIP 也额外放入了只读副本，方便未克隆前先浏览，但**修改必须在 Git 克隆出来的项目中完成**：

```powershell
Test-Path .\docs\INTERFACE_SPEC.md
Test-Path .\2.1.Linux网关\k7-gateway\docs\LoRa_E22接线与UART选择.md
Test-Path .\2.1.Linux网关\k7-gateway\README.md
```

三条命令都应输出 `True`。

## 开发方式：ADB、串口、SSH

日常优先使用 **ADB**。它通过 K7 的 USB 调试连接进入 Linux，即使 K7 尚未连上 WiFi/5G、尚未知道 IP 地址，也能工作；因此它是接手、部署和排障的首选方式。

### 1. ADB：推荐的日常开发入口

Windows 安装 Android SDK Platform-Tools 后，在项目外的 PowerShell 执行：

```powershell
adb devices
adb shell
```

`adb devices` 中应出现一个设备序列号，状态为 `device`。进入 `adb shell` 后看到的是 K7 Linux 的 shell；常用命令如下：

```powershell
# 检查开机服务和最近日志
adb shell "systemctl status k7-gateway.service --no-pager"
adb shell "systemctl status k7-network-watchdog.service --no-pager"
adb shell "journalctl -u k7-gateway.service -n 100 --no-pager"

# 检查 LoRa 串口、网络设备和默认路由
adb shell "ls -l /dev/ttyS3"
adb shell "nmcli device status; ip route"

# 从 K7 拉取日志到当前 Windows 目录
adb pull /var/log/k7-gateway .\k7-log-export
```

部署单个修改文件时，使用明确的源文件和目标文件，避免把目录错推成嵌套目录。例如：

```powershell
adb push .\2.1.Linux网关\k7-gateway\src\k7_gateway\config.py /root/k7-gateway/src/k7_gateway/config.py
adb push .\2.1.Linux网关\k7-gateway\systemd\k7-gateway.service /root/k7-gateway/systemd/k7-gateway.service
adb shell "cd /root/k7-gateway && sh scripts/install_systemd_service.sh"
adb shell "systemctl restart k7-gateway.service"
adb shell "journalctl -u k7-gateway.service -n 50 --no-pager"
```

不要使用类似 `adb push .\systemd /root/k7-gateway/` 的目录级命令：它可能把目录推为 `/root/k7-gateway/systemd/systemd`，导致服务文件没有实际更新。涉及多个文件或服务配置时，先读 `docs/K7项目交接指南.md` 中的完整部署流程。

### 2. 串口：ADB 不可用、看启动过程或系统异常时使用

K7 调试串口经 CH340 USB 转串口连接到 Windows。设备管理器中应显示为 `USB-SERIAL CH340 (COMx)`；若显示在“其他设备”，先安装 CH340 驱动。终端软件可使用 MobaXterm、PuTTY 或 Xshell。

串口参数固定为：

```text
Speed: 1500000 bps
Data bits: 8
Parity: None
Stop bits: 1
Flow control: None
```

串口适合观察 U-Boot/内核启动日志、在网络未通时登录 K7，以及排查 ADB 未识别。它不是批量部署的首选，因为复制大量命令容易丢字符或误粘贴。看到乱码时，先确认速率为 `1500000`，再检查 USB 线和 COM 口是否正确。

### 3. SSH：网络正常后的远程入口

SSH 需要 K7 已通过 WiFi 或 4G/5G 获得 IP，且 Windows 与 K7 在可达网络中。先通过 ADB 获取地址：

```powershell
adb shell "ip -br addr"
adb shell "hostname -I"
```

然后在 Windows 使用：

```powershell
ssh <K7登录用户名>@<K7_IP地址>
```

例如用户名由板上实际登录账户决定；历史串口提示符出现过 `kickpi@kickpi`，但不要据此猜测密码。首次接手应从板子的串口或 ADB 确认账户、密码和 SSH 服务状态：

```powershell
adb shell "systemctl is-active ssh; systemctl is-enabled ssh"
adb shell "whoami; hostname"
```

若 SSH 连不上，按顺序检查：K7 是否有默认路由、Windows 是否与 K7 同网段、`ssh` 服务是否 active、以及防火墙/热点是否隔离终端。没有网络时应退回 ADB，不要为了 SSH 去刷机。

### 4. 三种方式怎么选择

| 场景 | 首选方式 | 原因 |
| --- | --- | --- |
| 首次接手、改服务、看 K7 日志 | ADB | 不依赖网络，支持文件推送和命令执行 |
| 无法启动、ADB 不识别、需要看内核启动日志 | 串口 | 能看到最早期启动输出 |
| K7 已稳定联网，需要远程长期维护 | SSH | 不需要一直插调试 USB |

无论采用哪种入口，修改源代码后仍应在 Windows 项目目录执行 Git 工作流：先 `git status --short --branch`，完成一个小目标后验证、`git diff`、提交并推送。不要只在 `/root/k7-gateway` 上临时改而不回写 Git 源码，否则后续无法复现。

## 当前硬件和服务事实

- 板卡：KICKPI K7，RK3576，Ubuntu 24.04。
- LoRa 模块：E22-400T22D，连接 K7 UART3，Linux 设备名 `/dev/ttyS3`。
- 设备树目标：UART3 为 `okay`，I2C7 为 `disabled`。
- 节点板：STM32F767；Keil 工程与当前已编译 `工程文件.hex` 在交接包中。
- 5G 模块：Quectel RG200U-CN。无 SIM 卡或模块接触不良时，网络守护会回退 WiFi。
- 当前 K7 服务：`k7-gateway.service` 和 `k7-network-watchdog.service`，均已设置开机启动。
- WiFi 已验证可发布 HiveMQ 状态：`{"online":1,"transport":"wifi"}`。

RG200U 必须用合适的短 M2 螺丝固定。未固定时曾出现 USB 设备与 `enx*` 网卡反复消失；这不是软件或 Broker 能解决的问题。

## 绝对不要先做的事

1. 不要因为 LoRa、5G 或上位机问题就先重刷 K7。
2. 不要把官方全量镜像当作当前 UART3 版本的备份。
3. 不要把 `boot-resource-uart3.img` 当作 FactoryTool 的全量 `update.img`。
4. 不要手写 Rockchip 分区扇区偏移执行写入命令。
5. 不要提交或传播 WiFi 密码、SIM 卡信息、token、私钥、历史数据库。

## K7 接手验证顺序

先让 K7 正常上电，接上调试 USB。在 Windows 终端执行：

```powershell
adb devices
adb shell "systemctl is-active k7-gateway.service k7-network-watchdog.service"
adb shell "cat /proc/device-tree/serial@2ad60000/status; echo; cat /proc/device-tree/i2c@2aca0000/status; echo; ls -l /dev/ttyS3"
adb shell "nmcli device status; ip route"
```

期望：

```text
两个服务均为 active
UART3: okay
I2C7: disabled
/dev/ttyS3 存在
WiFi 或蜂窝网络存在 default route
```

LoRa 检查：

```powershell
adb shell "cd /root/k7-gateway && PYTHONPATH=src python3 -m k7_gateway listen-lora --device /dev/ttyS3 --seconds 30 --raw"
```

节点板上电并发送时，应该看到 `RX_HEX=` 和解析后的 JSON。详细协议和完整验收请读：

- `docs/K7项目交接指南.md`
- `docs/INTERFACE_SPEC.md`
- `2.1.Linux网关/k7-gateway/docs/network-watchdog.md`
